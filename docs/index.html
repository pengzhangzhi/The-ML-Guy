In short

Coding agents can now build a whole model on their own, but they also choose how it is graded. A scientist knows what better means, like the patients a team can call or the hundred designs a lab can make, but not always how to turn it into a score. So The ML Guy asks first, agrees the scoring with you, has a second agent try to break it, and then freezes it. As a model, it beats what you do today: 93 bright designs in a hundred, where picking by hand found 14. As a report, it argues against itself, and says where the model is weak. As a page, it fits how you will use it. Be exact about the problem, and leave the modelling open: any model, any library, on your own machine.

How it works

One conversation, then it works alone.

Everything that decides what a good model means is settled with you before any model is trained. Nothing about how to build one is.

with you

Ask.

It learns your machine, opens your data, and asks only what is missing.

with you

Agree.

What better means becomes a metric on a split, checked to tell good from bad.

mlguy score
a second agent

Audit.

A fresh agent with no stake hunts for leaks and outputs that score well while solving nothing.

you approve

Freeze.

The task is hashed and the test set moves out of reach.

mlguy init
on its own

Search.

Any model, any library. Every try is scored and recorded, then the test set is scored once.

mlguy submit · finish

Anatomy of a project

Strict about the problem. Free about the model.

task/First, the problem is pinned down
  • brief.md in your words, with your approval
  • the data and how it was split
  • evaluate.py, written for this problem
  • audit.md, from the agent that tried to break it
infer.pyOne fixed way to run the model
  • --model, --input, --output
  • the scoring and your page both call it
  • it may not read anything in task/
src/ · model/Everything else is the agent's
  • any architecture, any library
  • any code structure
  • what to try next, and when to stop
experiments/ · final/And a record nobody edits by hand
  • every score, with a snapshot of its code
  • the exact model that was scored
  • REPORT.md and app.py at the end

Until the end, the test split lives in ~/.mlguy/projects/<name>/, outside the project folder.

Give your agent the skills

The skills tell the agent how to run a project. The tool keeps it honest.

# Claude Code, for every project on this machine
cp -r skills/* ~/.claude/skills/

Codex reads AGENTS.md instead: point it at the skills, as INSTALL.md shows. Then open your agent next to your data and describe the problem.

Make it yours

  • agentClaude Code or Codex; the contract is a command line and files on disk
  • computeit learns your GPUs, Slurm and storage once, and asks which account to charge
  • budgetsubmissions are capped; other limits you set are kept by the agent and printed in the report
  • MLGUY_HOMEwhere the held-back test split and the task's hash live
  • --experimentship a simpler model than the top score, with --reason in the report

Good to know

It is early.

It has been run end to end by Claude Code and Codex on the five problems in the gallery.

There is no sandbox.

The agent runs with your permissions. The test data is protected against accidents, not against an agent that goes looking for it.

Compute is yours.

The framework never sees the compute, so it records GPU-hours and money but cannot cap them.
